Notarize release archives in CI and staple the app, so downloads open without Open Anyway.

**Changes**

- After packaging, submit with `xcrun notarytool submit --wait` using the App Store Connect API key (`--key` from a job-temp `.p8`, `--key-id`, `--issuer`). Write the key with mode 0600 under `$RUNNER_TEMP` and remove it in an `always()` step, like the signing keychain. On rejection, fetch and print `notarytool log` (it contains no secrets) and fail.
- App: notarize, `xcrun stapler staple` the `.app`, then build the final zip and its SHA-256 from the stapled bundle. Checksums must describe the published bytes.
- CLI: a bare Mach-O cannot be stapled. Notarize the CLI zip so Gatekeeper finds the ticket online; document that offline first runs need network access.
- Verify before publishing: `xcrun stapler validate`, `spctl -a -vv -t exec` on the app (expects `source=Notarized Developer ID`), `codesign --verify --deep --strict`. Any failure blocks the GitHub release.
- Keep the shape of `scripts/package-release.sh` simple: either a notarize step in CI or a small `scripts/notarize.sh` used by CI. Pick whichever keeps local packaging working without notary credentials (local builds skip notarization with a visible note).
- Extend the `workflow_dispatch` signing check to validate notary credentials (`notarytool history`) without submitting.
- Release notes: replace the self-signed/Open Anyway text with "Developer ID signed and notarized".

Rename the project from PanelCtl/panelctl to **DisplayPanel**, with the CLI command **`dp`**. Do a complete cutover in one change. There are no users, so add no aliases, shims, migration code or fallback reads of old names or paths.

**Why**

`ctl` makes the menu-bar app read like a dev utility. DisplayPanel is clear and natural; `dp` keeps the CLI short (verified: no `dp` binary on PATH, /usr/bin, /usr/sbin or Homebrew).

Rename directories with `git mv` so history follows. Use `DisplayPanel` for prose and type names, `displaypanel` for lowercase identifiers and paths, and `dp` only for the command and CLI-specific artifacts.

**Safety: existing recovery journal (blocking)**

`~/Library/Application Support/PanelCtl/Recovery/current.json` exists on the developer machine, alongside recovery-*.json and DP-9 evidence. After the rename, the app and `dp` read only `DisplayPanel/`, so an unresolved journal under the old path would be silently orphaned. That breaks the AGENTS.md rule to preserve unresolved journals.

Before merging, run the old `panelctl recovery status` (read-only) and record the output. If any display is removed or the journal is unresolved, stop and ask the user. Do not move, copy, delete or edit anything under ~/Library: no migration code, and no manual moves without explicit approval. No hardware writes are authorized by this task.

**Human-only steps (ask; don't block the code change)**

1. Rename the GitHub repo to `displaypanel` (`gh repo rename`). This needs explicit approval; afterwards update the `origin` remote.
2. Create the `DISPLAYPANEL_SIGNING_*` repo secrets with the same values as the old ones, then delete the old ones. Agents can't read secret values.
3. Re-grant macOS privacy permissions (Accessibility/Screen Recording, etc.) to DisplayPanel.app. TCC is keyed on the bundle ID.
4. Optionally clean up old local state: the old Application Support dir, the `com.brettinternet.panelctl` defaults domain, the signing keychain, and the installed `panelctl` binary.

**Notes**

- `defaults domains` on the dev machine lists about 8,400 leaked test suites (`panelctl-snooze-*`, `panelctl-settings-window-*`, …). Tests are not removing their persistent domains. That's out of scope here, but keep the renamed prefix consistent so a follow-up fix can find them; file a separate task if none exists.
- Follow the test-selection rules in AGENTS.md. Don't set `PANELCTL_TEST_INTERACTIVE_UI` / `DISPLAYPANEL_TEST_INTERACTIVE_UI` without user approval.

After wake, a hidden monitor can come back off-input with no DP signal, for example the S2721DGF with Monitor Auto Select disabled. The display is then online and inactive but no longer mirrored, and the journal goes to `needsAttention`. Restore can't run from that state because `canAttemptGuardedRecoveryShow` requires the target to match a present display. Today the only way back is switching inputs by hand from the monitor's on-screen menu. Once the mirror returns, a0464c9 clears the failed wake journal back to `mirrored`.

**Decision needed before implementation**

Should Restore from this state send a DDC input switch to the hidden monitor's configured return input, then wait for it to rejoin and continue as a normal Show? That is a hardware write from a recovery state. DP-9/DP-10 rules apply: explicit human approval before any live trial, strict identity checks, no guessing IDs and no automatic escalation.

**Options**

1. Keep it manual: Settings explains the monitor is off-input and tells you to switch its input. No DDC write.
2. Guarded switch: allow it only when the journal's target identity, DDC service match and configured return input are all unambiguous, then reuse the existing input-return wait (`canWaitForInputReturnShow`).

Offline work only, using fake writers, until the scope is approved.

## Acceptance criteria

- [ ] Approach chosen (manual guidance or guarded DDC input switch) and recorded here
- [ ] If guarded switch: offline implementation with fake writers; no live DDC write without scoped human approval
- [ ] Needs-recovery off-input state explains the next step in Settings

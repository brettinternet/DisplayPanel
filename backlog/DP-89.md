Stop the test suites from leaving persistent state on the developer machine, and remove what has already accumulated.

**Evidence (2026-10-26, dev machine)**

- `~/Library/Preferences` holds about 8,400 `panelctl-*.plist` files, one per test run. They have unique suffixes (a UUID or PID), e.g. `panelctl-snooze-<UUID>.plist` and `panelctl-settings-window-<PID>.plist`. The biggest groups: disconnect 1,825, run-rule 627, arrangement-app 502, display-hide-app 474, settings-window 307, and about 257 each for countdown, snooze, sleep-now, until-tomorrow, first-run, membership, menu-bar-icon and display-recovery.
- About 8,250 of them are empty (42 bytes). Most tests already call `removePersistentDomain(forName:)`, which clears the contents, but cfprefsd leaves the file behind. With a unique suite name on every run, those files pile up forever.
- About 150 are not empty. Those suites skip cleanup on some paths (a crash, an early throw, a child helper process, or a fixture written by a subprocess): display-actions (57), display-hide-app (45), automation-fixture (32), display-action-fixture/editor-fixture/progress (about 6 each) and rules-aggregate (1).
- `$TMPDIR` holds about 119 leftover `panelctl-*` entries: lease-tests (30), blackout-hide (10), five each of the control-* fixtures (exit, intent, latest, restart, retry-limit), action-rearm, countdown, display-recovery, late-status, membership, playback-status, waiting-input and service, plus a stale `panelctl-app-control.sock` and a few mktemp dirs from older review work (`panelctl-task85-*`, `panelctl-recovery-details-ui.*`). SwiftPM's own `_Users_…_.build*.lock` files are not ours; leave them.

**Fix**

1. Find every UserDefaults suite and temp path that tests create: `rg -n 'UserDefaults\(suiteName|suiteName:|removePersistentDomain|temporaryDirectory|NSTemporaryDirectory|mkdtemp|mktemp' Tests scripts Sources`. Check fixture helpers that child processes launch too, such as the `*_FIXTURE_OUTPUT` and `*_TEST_*` environment-variable paths.
2. Stop the build-up at its source. Prefer one existing or extended test helper (reuse it if one exists; announce it as a CODE PATTERN if not) that:
   - uses a deterministic suite name per test, e.g. `<prefix>-test-<Suite>.<test>`, with no UUID or PID suffix, so a rerun reuses the same file instead of adding one;
   - clears the domain in both setUp and tearDown, so a crashed earlier run is cleaned up on the next one;
   - registers cleanup with `addTeardownBlock`, or `defer` right after creation, so early throws still clean up.

   If tests must run in parallel, uniqueness can come from the test name rather than a random value. Only use a random suffix where a test needs isolation it can't get otherwise, and then delete the plist file in teardown too.
3. Apply the same rule to temp directories and sockets: create them under one per-test directory and remove it in a teardown block. Child helper processes must write inside a directory the parent test owns and removes.
4. Leave production code paths alone unless a test seam requires it. Don't change real app defaults (`com.brettinternet.<app>`) or Application Support behaviour.

**One-time cleanup of existing leftovers (authorized by the user)**

Use `trash`, never `rm`. Match only test-generated names:

- Files in `~/Library/Preferences` whose names start with the test prefix followed by a hyphen. That's `panelctl-*` now, and the new `displaypanel-*` prefix too if DP-88 has landed. Never touch `com.brettinternet.*.plist`.
- `$TMPDIR` entries with the same prefixes, excluding SwiftPM `_Users_*` locks.

Before trashing, list the matches and their count and record them in a note. Afterwards run `killall cfprefsd` (safe; it respawns), or confirm `defaults domains` no longer lists them. Do **not** touch `~/Library/Application Support/PanelCtl` or `DisplayPanel` (that holds recovery journals and DP-9 evidence), the real app defaults domain, or the signing keychain.

**Ordering**

This task depends on DP-88, so the fix uses the new names. Clean up both the old and new prefixes in the same pass.

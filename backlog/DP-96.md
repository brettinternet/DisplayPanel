With monitor Auto Select off, Show's DDC input write is what makes the monitor relink. The input-return settle (prepareShow) accepted two matching samples 200 ms apart within 5 s, so it either timed out while the relink was still in progress (2026-10-27: AW3425DW "original mode unavailable") or restored before the relink (S2721DGF came back logically but blank). Errors through MirrorController.fallback also showed a doubled "display recovery:" prefix, which pushed the cause out of the 64-byte Action step summary. With Auto Select off, a shown monitor left on the other computer's input also had no in-app way back.

## Acceptance criteria

- [x] After an input write that changed the input, Show waits up to 15 s and restores only after seeing the target relink (offline/changed topology) then two matching ready samples, or after 5 s of continuous ready stability with no relink; unchanged-input Show keeps the fast path. Fake-backed tests cover both.
  Evidence: DisplayMirroring.prepareShow: 75x200ms window after switched input, relink-or-25-quiet-match gate; unchanged keeps 26-sample fast path. swift test --filter DisplayMirroringTests.testShowAfterInputSwitchWaitsForRelinkOrQuietFloor passed (relink <10 captures, no relink >25).
- [x] Recovery errors wrapped by fallback and the Show write path carry a single display recovery: prefix.
  Evidence: RecoveryError.reason(of:) used by fallback and prepareShow rethrow; description adds prefix once. DisplayPanelCoreTests 337 passed.
